# 独立レビューの依頼資料

正本と実際の成果物を独立して評価できる資料を渡す。採用理由は示すが、統括担当の結論への同意を求めない。レビュー担当の選び方と進行条件は [SKILL.md](../SKILL.md) に従う。

## 提案レビュー

```text
役割: 独立した設計レビュー。ファイル編集・外部操作・ゴール状態操作・追加委任は禁止。
目的: ゴールのうち、この作業で満たす条件。
範囲: 対象外、担当ファイル、契約、許可範囲、他担当との境界。
入力: 正本の仕様、現在のコードと対象版、既存の検証結果。
提案: 具体的な変更と採用理由。
受入条件: 必要な証拠、失敗ケース、必要に応じた独立の参照結果。
確認事項: 要件の漏れ、前提、不変条件、検証の独立性、残る不確実性。
返却: 承認可能 / 修正必要 / 情報不足と、その理由、確認した対象版・範囲。
指摘: 識別子を付け、必須修正と任意改善を分ける。箇所、再現条件、影響、必要な検証を示す。
情報不足の場合: 判定に必要な追加資料・検証を具体的に示す。
指摘がない場合: 確認した範囲と検証上の限界を示す。
```

## 実装レビュー

提案時の資料に加え、実際の差分、対象版、実行済みの検証結果を渡す。変更に応じて、並行実行、エラー、再試行、権限、移行、復旧を評価対象にする。コードとしての判断と、未実施の統合検証・引渡し条件を区別させる。

## 再レビュー

前回の指摘ごとに、修正差分または不採用の根拠、回帰検証を対応づけて渡し、解消・未解消を返してもらう。契約を変えた場合は提案と完了条件も更新する。無関係な長い履歴を追加しない。

## 別セッション・人への引渡し

同じ作業ツリーや会話履歴を参照できるとは限らない。共有が許可された必要最小限の仕様、対象版、差分、検証結果を資料に含める。ファイルへアクセスできない相手にローカルパスだけを渡さない。秘密情報や不要な個人情報は除く。

返却結果の対象版を現在の成果物と照合し、以後の変更がレビュー範囲に影響する場合は再レビューする。未受領の返答や自己レビューで独立レビューを代用しない。
