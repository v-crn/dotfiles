# 使用例と継続の記録

## サービス共通の依頼例

```text
goal-driven-development の手順で、指定した不具合を修正してください。
完了条件は、原因の特定、修正、必要な回帰テスト、提案と実装の独立レビュー、
検証結果の引渡しです。ローカルの修正までを対象とします。
```

```text
goal-driven-development の手順で、指定したIssueを完了してください。
完了条件は、現行仕様に対応する実装、必要なテスト、独立レビューの必須指摘解消、
文書更新、PRと検証結果の引渡しです。最後に開発者へ確認を依頼してください。
push・PR作成は今回は許可します。マージ・本番公開は対象外です。
```

上記の許可と完了条件は例であり、Skillの既定ではない。スキルの登録・呼び出し構文は利用環境に従う。自動ロードされない環境では、本文と必要な参照資料を渡してこの手順の使用を依頼する。

## 環境固有の機能を使う場合

- Codexのスキル呼び出し例は `$goal-driven-development`。`agents/openai.yaml` はCodex向けの表示・初期プロンプト用メタデータであり、共通手順はこれに依存しない。
- Claude・Geminiを含め、委任・モデル選択・状態管理は現在の実行環境が提供する機能だけを使う。他サービスのコマンドやツール名をそのまま実行しない。
- 永続ゴール機能を明示的に依頼された場合は、その環境の現在のツール契約に従う。状態名、停止条件、再開方法を推測しない。機能がなければ作業記録で追跡し、自動継続を設定したとは説明しない。

## 既存作業を続ける

```text
goal-driven-development の手順で、既存のゴールを続けてください。
継続記録と現在の成果物を照合し、次の未完了条件から進めてください。
```

次の作業は既存ゴールの範囲内で選ぶ。許可を引き継ぎ、環境や担当が変わった場合はレビュー手段と資料へのアクセスを再確認する。

## 継続に必要な記録

| 項目 | 残す内容 |
| --- | --- |
| ゴール | 目指す状態、対象外、完了条件、指定がある場合の予算 |
| 許可 | ローカル作業、Issue操作、push、PR作成、マージ、公開それぞれの範囲 |
| 作業 | 担当、境界、依存関係、完了条件、次の作業 |
| 担当・環境 | 実装とレビューの担当、判明しているモデル識別子、選択理由、利用上の制約 |
| 証拠 | 対象版、差分、検証コマンドと結果、参照結果、未確認事項 |
| レビュー | 対象版、判定、必須指摘と解消状況、任意改善の採否、再レビューの要否 |
| 引渡し・再開 | 成果物、必要ならURLと到達確認、人の操作、残作業、再開条件 |

既存Issue・PRやプロジェクト規則に沿った作業表を使う。正本の仕様には現行契約を反映し、進捗履歴を混ぜない。記録には秘密情報や不要な個人情報を含めない。
